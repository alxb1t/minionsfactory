## [Unreleased]

### Added

- Findings-file reader (`orchestrator/findings.py`) — `read_findings_state(path) -> FindingsState | None` reads a role's findings file into a typed, validated convergence verdict (`verdict` / `open_blocking` / `round` / `head`), reusing `state.py`'s `parse_frontmatter` (no new parser). `FindingsState` is a frozen Pydantic model (a trust-boundary read *with structure worth validating* — ints to coerce, a closed `Literal["clean","changes-requested"]` verdict that rejects a typo at read time), so `model_validate` coerces the ints and ignores the extra frontmatter keys in one line. A missing file returns `None` (a not-yet-run role, not a crash), keeping `verdict` strict and forcing callers to handle "not run". This is the orchestrator's un-gameable convergence signal — owned by the verify pass, read from disk, never trusted from the fixer's word. Unit-tested (parse + coercion, `None` on missing, `ValidationError` on an unknown verdict).
- Diff supply for read-only roles (`orchestrator/diff.py`) — `compute_diff(repo, base, head)` returns the diff for a commit range via list-argv git (`git diff base..head`, no shell) behind an injected runner seam (the real `_run_git` uses `check=True` — a failing diff is an error to surface, unlike the gate's captured red). Two scopes serve two callers: frozen `base..HEAD` (the whole feature) for the fan-out, and `head..HEAD` (just the fix) for scoped re-verify. `run_role_with_diff(...)` writes the diff to a file under the target's `.minions/` and runs the role, so the prompt carries only the path — a large diff never bloats it. The role-agnostic primitive the P4 fan-out will compose per role. Unit-tested behind an injected runner + `FakeProvider`; no real git or `claude`.
- Read-only role permission profile (`read_only_profile(findings_file)` in `orchestrator/provider.py`) — denies `Bash` and `Edit` (bare-tool denies, the sound regime of the v0.1 Q1 finding) and allows `Write` only to the role's single findings file (`Write(<path>)`). A factory over the existing `Profile` (no schema change; `build_command` emits it unchanged), deliberately avoiding a bare-`Write` deny so deny-precedence can't cancel the scoped allow. `Bash` denied is why a read-only role can't `git diff` itself — hence the orchestrator-supplied diff above.
- Status/event stream (`orchestrator/status.py`) — the run is now observable without any LLM in the loop. A typed, timestamped **`Event`** schema (a Pydantic discriminated union on `kind`: `phase-start`, `coder-spawn`, `coder-result`, `gate-step`, `advance`, `halt`, `run-summary`; timestamps are `AwareDatetime`, rejecting naive datetimes at the boundary) is written to disk two ways — an **append-only history** (`events.jsonl`, one JSON line per event) and a **current-state snapshot** (`status.json`, the latest event) — via a single `emit` that keeps them in step. A pure, exhaustive `render(event) -> str` (a `match` with no `case _`, so `ty` enforces a line for every variant) projects the stream to stdout, and `is_in_progress` derives "a role is still running" from a dangling `coder-spawn` in the snapshot. Fully unit-tested (round-trip, snapshot, render, in-progress) with no disk-less logic left untested.
- Instrumented the build-spine loop: `driver.run()` gains an injected `emit_event` sink (defaulting to a no-op — observability is a side-channel the driver's logic never depends on) and emits the event sequence around each phase. The coder's returned `RoleResult` is now **captured** to fill the `coder-result` event while `decide` still **discards** it for the advance verdict (surfaced for observation, never trusted); every terminal path — complete, decision-halt, and the runaway guard — ends with a `run-summary`. Instrumentation covered by spy-injected tests (emitted kind-sequence + key fields).
- Live status sink wired in `orchestrator/__main__.py`: `_make_emitter` roots an `events.jsonl` + `status.json` pair under the target's `.minions/` (fresh log per run) and `emit_and_render` writes each event to disk **and** renders it to stdout, so a real run is no longer silent.
- `Makefile` with `make fix` (mutating: `ruff format` + `ruff check --fix`) and `make gate` (verify-only, the definition of done: `ruff format --check` → `ruff check` → `ty check` → `pytest`) — kept strictly separate so the gate can never auto-fix its way to green.

## [0.1.0] — 2026-08-17

### Added

- Project scaffolding: role-independent `CLAUDE.md`, vault wiring (`.env` → `VAULT_PROJECT_DIR`), `.gitignore`, `.env.example`, and this changelog.
- Minimal `pyproject.toml` (uv-managed, run-from-source, no runtime deps) + committed `uv.lock`.
- Strict quality gate, dogfooded on this repo: `ruff` (format + lint with `D` docstrings and `ANN` annotations, `pep257` convention; `D` waived for `tests/`), `ty` in strict mode (`error-on-warning`), and `pytest` (`pythonpath` set for run-from-source imports) — all as a dev-only dependency group.
- `orchestrator/` package skeleton with a typed, docstringed `describe()` and a passing smoke test.
- GitHub Actions CI (`.github/workflows/ci.yml`) mirroring the gate on every push/PR: `uv sync --locked` → ruff format → ruff lint → ty → pytest.
- Proven role prompts copied into `prompts/` (`coder`, `reviewer`, `security`, `simplify`, `release`); v0.1 drives the coder, the rest ride along as reference.
- Provider seam (`orchestrator/provider.py`): a `Provider` Protocol the driver depends on, a real `ClaudeCodeProvider` (headless `claude -p --output-format json`, list-argv — never a shell string), and a scripted `FakeProvider` test double. Supported by a typed `RoleResult` (Pydantic, parsed from the CLI JSON and tolerant of unknown fields), a `Profile` permission profile (frozen dataclass), and a pure `build_command` argv builder — the pure parse/build halves are unit-tested; real `claude` is never spawned in tests.
- Runtime dependency `pydantic`, to model and validate the headless CLI result at the trust boundary.
- Developer docs under `docs/` (raw markdown, no build tooling): `architecture.md` (invariants + component/dependency graph), `data-flow.md` (sequence/flow diagrams for `run_role` and the planned loop), and a per-package API reference `modules/orchestrator.md`.
- Gate runner (`orchestrator/gate.py`): the orchestrator runs the target repo's own quality gate itself and returns a typed `GateResult` (`passed` + per-step `command`/`exit_code`/`output`). The ordered command list is read from the target's `minions.toml` (`tomllib`, language-neutral — a JS target needs no orchestrator change), each command runs with no shell (`shlex.split`), and the run stops at the first failing step. Exposed as a `Gate` Protocol with a real `SubprocessGate` (injectable command executor) and a scripted `FakeGate` double — the fail-fast logic is unit-tested; real tools are never spawned in tests.
- Plan-state reader (`orchestrator/state.py`): reconstructs "where are we" purely from disk into a typed `PlanState` (`current_phase` + `phaseN` flags + git `head`). Selects the highest-version plan (`vX.Y_*implementation_plan.md`, ignoring `archive/` via a shallow glob and integer version comparison), parses the plan's YAML frontmatter with a small stdlib-only extractor (no new dependency), and reads the target repo's git HEAD. The composition is unit-tested via an injected head reader — git is never spawned in tests.
- Build-spine driver (`orchestrator/driver.py`): the deterministic loop — read `PlanState` → spawn the coder via the provider → the orchestrator runs the gate → **detect** advance (a new commit **and** a moved `current_phase`) → continue or halt. Halts on a coder HALT report, a red gate, or a non-advancing phase; resumes for free by re-reading disk each run; a runaway guard caps iterations. The pure `decide` verdict is split from the effectful loop, and the full matrix (advance / halt-on-halt-report / halt-on-red / halt-on-non-advance / resume) is unit-tested behind `FakeProvider` + `FakeGate` — no LLM, no real git.
- Run-from-source entry (`orchestrator/__main__.py`): `python -m orchestrator run --repo <target>` wires the real `ClaudeCodeProvider` + `SubprocessGate` into the driver and resolves the target's vault from its `.env`.
- Root `README.md`: brief overview, invariants, run-from-source usage (target `.env` + `minions.toml`), the quality gate, and pointers to `docs/`.
- `prompts/coder-per-phase.md` — the per-phase (orchestrated) coder variant: builds exactly one `current_phase` per spawn then stops, so the driver runs the gate + detects advance per phase. `python -m orchestrator run` now uses it; the warm full-plan `coder.md` remains for a future run-mode.
