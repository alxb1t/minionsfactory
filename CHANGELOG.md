## [Unreleased]

### Added

- **The release version is declared by the change** (change `0005-change-cutover`, phase 1). `ChangeState` gains `version: str`, and `read_change_state` now reads `openspec/changes/<id>/proposal.md`'s leading YAML frontmatter through the existing `parse_frontmatter` and a new contract guard (`read_change_version`): a `proposal.md` with no frontmatter, no `version` key, or a `version` that is not `vX.Y` raises `PlanContractError` naming the file and the field, at read time — before any role is spawned. The change is the unit of release, so the version travels with it instead of being derived from a vault plan's filename. `skills/mf-forge/SKILL.md` teaches the convention in the same breath, so the next `mf-`authored change ships with the frontmatter rather than being refused at preflight.

### Changed

- **Findings live at `<vault>/findings/<change-id>_<role>.md`** (change `0005-change-cutover`, phase 2). The findings home moves out of the retired `implementation_plans/` and is keyed to the **change id** — the same identifier as the change directory and the `Change:` commit trailer. One resolution site, `findings_path(vault_dir, change_id, role)` in `orchestrator/findings.py`, replaces the three call sites that each computed the path by hand (the fan-out, the converge loop and the release stage), so the three cannot drift. `run_fanout` now takes `change_id` in place of `version` and **creates `<vault>/findings/` before the first spawn** — a read-only role is granted `Write(<its findings file>)` and denied `Bash`, so it cannot create the directory itself, and a findings file that never lands would read as not-clean. The fan-out Inputs block now names the in-tree change directory (proposal · design · tasks) instead of a vault plan file, and `_make_fanout` / `_make_converge` resolve it with `select_change(repo)`.

## [0.4.0] - 2026-08-23

### Added

- **Planning rubrics — the v0.4 planning surface begins** (change `0004-planning-skills`, phase 1; hand-authored, doc-only). Three shared rubrics under `skills/rubrics/` define "done" for each planning artifact — the planning-side analog of the machine gate: `prd-readiness.md` (drives `mf-order`, gates `mf-gauge`), `feasibility.md` (produced by `mf-blueprint`, re-checked by `mf-inspect`; the 4-way `feasible` / `feasible-with-caveats` / `needs-precursor` / `infeasible-as-specified` verdict), `conformance.md` (gates `mf-inspect`), and `README.md` holding the shared **(M) machine / (J) judgment** criterion split, the verdict/severity conventions, and the skill→rubric map. The change was scaffolded first (`openspec/changes/0004-planning-skills/` — proposal · design · tasks · **N-A spec delta**, PRD Option 1) so every commit carries a `Change: 0004-planning-skills` trailer. Markdown-only — the repo gate stays green (`specs check` parses `spec.md` only, so the N-A delta adds no scenarios).
- **`mf-order` + `mf-gauge` skills** (change `0004-planning-skills`, phase 2) — the first producer→checker pair of the planning line. `skills/mf-order/SKILL.md`: an interactive intake interview (runs in the main session) that drives a raw idea to a well-defined `prd/vX.Y_<name>.md` against the prd-readiness rubric — starts small, resolves research inline (no `TBD`), and splits multi-feature asks into separate versioned PRDs. `skills/mf-gauge/SKILL.md`: an independent readiness gate that **spawns a fresh, blind subagent** (given only the PRD + rubric + findings paths, never the interview context) to check each rubric criterion — (M) mechanically (no TBD markers, Non-goals present, version declared, non-empty acceptance) and (J) by judgment — and writes `prd/vX.Y_gauge.md` with a `clean | changes-requested` verdict. Independence lives inside the check-skill, so it holds whether run manually or under `mf-line`. Markdown-only; repo gate unaffected.
- **`mf-blueprint` skill** (change `0004-planning-skills`, phase 3) — the feasibility spike that closes the feasibility gap. `skills/mf-blueprint/SKILL.md` runs with cwd = the target repo, reads the PRD (via `.env` → `VAULT_PROJECT_DIR`) against the **real codebase**, and writes `prd/vX.Y_design.md` per the feasibility rubric (approach with real paths · architecture impact · effort/phase count · blockers/prereqs · alternatives · risks). It emits the 4-way verdict — `feasible` / `feasible-with-caveats` (→ `mf-forge`) or `needs-precursor` / `infeasible-as-specified` (→ HALT: rescope or precursor version) — as a human go/no-go gate, catching "infeasible / needs-refactor / wrong-size" at planning time rather than mid-execution. Producer in the main session; `mf-inspect` re-checks the design independently downstream. Markdown-only; repo gate unaffected.
- **`mf-forge` skill** (change `0004-planning-skills`, phase 4) — renders an approved PRD + design proposition into an execution-ready **openspec change**. `skills/mf-forge/SKILL.md` runs with cwd = the repo, reads the vault PRD + `vX.Y_design.md` (via `.env`), determines the next change id `NNNN-<name>`, and writes all four artifacts — `proposal.md` (why/what/approach/scope/success), `design.md` (the sanitized *how*, no open questions), `tasks.md` (a `## Progress` checklist over **code+commit-only** phases; no research/design-lock phase), and the `specs/` delta (each PRD acceptance clause → a keyed WHEN/THEN scenario, or an N-A `specs/README.md` for a doc-only change). The private→public crossing — only the sanitized, execution-ready subset lands in the repo; commits carry a `Change: NNNN-<name>` trailer. Hands off to `mf-inspect`; never folds/archives (that's the release role). Markdown-only; repo gate unaffected.
- **`mf-inspect` skill** (change `0004-planning-skills`, phase 5) — the final gate before execution: does the openspec change faithfully render the PRD and is it execution-ready? `skills/mf-inspect/SKILL.md` runs with cwd = the repo and **spawns a fresh, blind subagent** (given only the PRD + change dir + conformance/feasibility rubrics + findings paths) that checks completeness (nothing dropped), no scope creep (nothing unauthorized added), bidirectional trace (spec-delta scenarios ↔ PRD acceptance), a real `design.md`, execution-ready **code+commit-only** phases (a research phase is blocking), contract completeness (M), and design soundness against the real codebase. Writes `prd/vX.Y_inspect.md` (`clean | changes-requested`, `open → fixed → verified` status machine) and loops fix→re-inspect until clean — the planning-side mirror of the execution fresh reviewer. Markdown-only; repo gate unaffected.
- **`mf-line` skill** (change `0004-planning-skills`, phase 6) — the planning-line conductor. `skills/mf-line/SKILL.md` runs the full sequence Order → Gauge → Blueprint → Forge → Inspect end-to-end so the human only answers the interview, reads the docs, and makes the go/no-go calls: interactive stages run in the main session, the **checks are delegated to fresh, blind subagents** (via `mf-gauge` / `mf-inspect`), and it pauses at the human gates (after Order, the Blueprint go/no-go, after Inspect). Handles the loop-backs — gauge `changes-requested` → `mf-order`; blueprint `needs-precursor`/`infeasible` → HALT; inspect `changes-requested` → re-`mf-forge` → re-inspect until clean. An **LLM conductor** for now (the deterministic `minions author` CLI is the backlogged no-LLM successor); independence still holds because it lives inside the check-skills. Markdown-only; repo gate unaffected.
- **`template/vault-pm/` + skill install/uninstall** (change `0004-planning-skills`, phase 7) — completes the v0.4 planning surface. `template/vault-pm/` is a filled worked example of the planning-vault layout (a fictional "Tasknip" CLI: `overview` · `roadmap` · `prd/` with an example PRD · `backlog` · `log` · `decisions`), documenting the vault contract by example (later stamped by `minions bootstrap`, v0.8). `make install-skills` symlinks `skills/mf-*` + `skills/rubrics` into `~/.claude/skills/` (repo edits stay live) and `make uninstall-skills` removes them (leaving other skills untouched); the README gains a "Planning skills" section documenting the line + install/uninstall. Markdown / Makefile only; repo gate unaffected.

### Added

- Spec-delta **fold** + release-gate traceability predicates (`orchestrator/release.py`) — the machinery that makes a change's delta *living* and gates commit-to-change traceability (change `0003-sdd-adoption`, phase 5; R3/R7). `fold_change(repo, change_id, dry_run=False)` folds `changes/<id>/specs/` into the top-level `specs/`: **ADDED** adds a requirement, **MODIFIED** overwrites the **whole** requirement (upsert by title, not a patch/append), **REMOVED** deletes it (title-keyed via a small `### Requirement:` block parser, `_parse_requirement_blocks` + `_apply_fold`). `dry_run=True` reports the planned `FoldEdit`s and writes nothing. After writing it runs a **verify-after-fold** validator (`specs check`) and **HALTs without moving the change** if `specs/` is invalid; on success it moves `changes/<id>/` → `changes/archive/<id>/`. It is **idempotent** — the upsert semantics reproduce identical text, so a re-fold (resolving the delta from `archive/`) writes nothing and moves nothing. Two new **pure** blockers join the `verify_release_gate` first-non-None scan (defaults keep it non-blocking until the caller gathers the facts): `_specs_blocker(specs_valid, change_folded)` and `_trailer_blocker(commits, known_change_ids)` — the latter blocks and **names** any `base..HEAD` commit missing a `Change:` trailer or carrying one that resolves to no known (active/archived) change, over a `Commit(sha, change)` list the effectful caller gathers (the verdict stays pure). `prepare_release` gains a `change_id` so the **release commit carries its own `Change:` trailer**; the never-push / never-merge boundary and the fold + archive are all local. Built and fake-tested (tmp `specs/` + `changes/<id>/` dirs, `FakeGate`, injected validator, fake commit lists); the real 0003 delta stays unfolded until the release step after all phases.

### Changed

- Reviewer prompt (`prompts/reviewer.md`) re-anchors its "Acceptance met" axis onto **scenarios** and adds the spec-conformance judgment (change `0003-sdd-adoption`, phase 4; R2). The change's `changes/<id>/specs/` delta *is* the acceptance now: the reviewer judges each scenario and flags — as `blocking` — a delta that is **not genuinely implemented** (green by omission / stub / happy-path shortcut), **not genuinely test-backed** (a test bound to the scenario key that does not exercise its WHEN/THEN — a tautology, a mock over the behavior, or an adjacent proof), or **incoherent vs the diff** (the spec and the code disagree, so the delta is not a **coherent** description). This draws the seam `specs check` can't: the checker proves a proving test *exists* (structural); the reviewer supplies the judgment that it *bites*. The other review axes (gate-integrity, correctness, cross-phase, conventions, test-quality, security) are unchanged. Prompt-only — no code, no test; the R2 scenario stays `Layers: e2e` (reserved for the v0.7 tester), so `specs check` is unaffected.

### Added

- Living behavioral specs for the `converge` and `release` capabilities (`specs/converge/spec.md`, `specs/release/spec.md`) — the first **shipped** specs in the top-level `specs/` tree (not a delta, no fold; change `0003-sdd-adoption`, phase 3). Authored in OpenSpec format (normative `SHALL` requirements, keyed `unit` scenarios) documenting only behavior that already exists in `converge.py` / `release.py` and is genuinely test-backed: converge's converge-to-clean loop (already-clean / fix-then-verified / reopen-then-clears) and its bounded, gate-guarded termination (round-cap / red-gate halts); release's gate preconditions, fail-closed backlog/changelog guards, changelog-cut + version-bump, and prepare-or-refuse-never-ship. Each of the 23 scenarios is bound to its proving test via `@pytest.mark.spec("<key>")` — **no behavior changed**, the existing tests are the proofs. The spec-binding checker is now **enforcing live** on these two capabilities: an unbound scenario orphans and reddens the gate (verified by temporarily unbinding a test), and the phase-1 seeded orphan/dangling tests confirm the checker names a missing binding or an unknown key.
- In-tree change-state reader (`orchestrator/state.py`, sibling to the vault-plan reader) — the framework now reconstructs "where are we" for a change directly from the repo, with no vault hop (change `0003-sdd-adoption`, phase 2; R4/R5). `read_change_state(repo)` resolves the active change dir under `<repo>/changes/` (`select_change` — highest numeric version-id, `changes/archive/` excluded), refuses a malformed change through the contract-guard, and parses `tasks.md`'s `## Progress` checklist (`parse_progress` — `- [ ] N — <title>` items, opening at the `## Progress` heading and closing at the next `## ` so checkbox-shaped prose elsewhere never leaks in) into an ordered `tuple[Phase, ...]`; `ChangeState` exposes `current` (the first unchecked phase, or `None` when complete), `is_complete`, and `current_index` (the advance cursor). `validate_change` reuses `PlanContractError` semantics to refuse a change missing any of `proposal.md` / `design.md` / `tasks.md` / `specs/` at read time with a diagnostic naming the missing artifact — never a silent empty state. `change_advanced(before, after)` re-expresses the plan advance signal over change-state — a new commit AND the current-phase index moved — deterministically (no LLM), so an advance is detected, not trusted. Built and unit-tested as a ready-for-v0.5 sibling; the driver keeps running the vault-plan reader until the loop self-hosts on changes at v0.5 (unchanged here). Dogfooded: this change's own `tasks.md` parses under the reader.
- Spec-binding checker (`orchestrator/specs.py`) + `python -m orchestrator specs check` subcommand — the mechanism that enforces spec-driven development on this repo (change `0003-sdd-adoption`, phase 1). A pure, stdlib-only module (`ast`, `pathlib`, `tomllib` — no new dependency) that reads two sides of the scenario↔test binding from disk and compares them: the **spec side** parses scenario keys (`Key:` + `Layers:` bullets) from `specs/**/spec.md` (shipped) and each active `changes/*/specs/**/spec.md` delta (`changes/archive/` excluded; delta `ADDED`/`MODIFIED` keys are resolvable-but-pending, `REMOVED` subtracts), and the **test side** statically collects `@pytest.mark.spec(...)` / `@pytest.mark.spec_exempt(...)` markers with `ast` — the checker never imports or runs the tests or the gate. Three checks: **orphan** (a shipped `unit`-layer scenario with no proving test — pending delta scenarios are exempt until folded), **dangling** (a `spec` marker whose key resolves to no scenario), and — under `--strict`, off by default — **traceability** (every collected test carries a `spec` or `spec_exempt` marker). Exit 0 clean / 1 on any violation, naming each. Layer-aware (v0.3 enforces `unit`; `e2e` recorded, reserved). Wired as the final step of MF's own gate (`.minions/minions.toml`, `Makefile`, `.github/workflows/ci.yml`) — a green no-op until specs exist. `spec` / `spec_exempt` registered in `pyproject` `[tool.pytest.ini_options].markers`.

## [0.2.0] — 2026-08-21

### Added

- Preflight / contract guard (`orchestrator/state.py`) — the orchestrator's fail-closed read-side of the target contract, checked **before any spend**. `validate_plan(frontmatter)` refuses a malformed plan at read time (no `---` fence · missing `current_phase` · no `phaseN` flags · a non-code phase status outside `{done, wip, planned, todo}`) with a specific `PlanContractError` per violation — catching the *silent* failure where a zero-phase plan would read as already "complete", and the non-code-phase case the driver would otherwise false-halt on mid-run (the execution-side mirror of `/plan-check`; a non-code phase can't be told from a code phase structurally, so an out-of-vocabulary status *is* the signal). `read_plan_state` now validates before assembling. `verify_vault_access(repo, vault)` preflights that the target's `.claude/settings.local.json` grants the coder vault write access (the vault dir or an ancestor under `additionalDirectories`), raising `PreflightError` otherwise. `__main__` runs both as a zero-token preflight that prints a clean diagnostic and exits `1` before spawning anything.
- Release automation (`orchestrator/release.py`) — the run's last deterministic stage: verify the release gate, then prepare the release locally and **halt for the human to merge + push** (the boundary never crosses — prepare locally, the human ships). `verify_release_gate(...) -> ReleaseVerdict` is **pure** — the release-time analog of `driver.decide`, judging already-gathered facts (gate result · the three findings `clean` · backlog current-release section closed · release tag free · CHANGELOG `[Unreleased]` non-empty · clean tree) as one first-non-`None` scan over `str | None` blockers, so it is unit-tested with plain data (no fakes needed). The predicates **fail closed**: a malformed backlog (missing current-release section) or an empty/missing `[Unreleased]` blocks release rather than silently passing (absence of evidence ≠ evidence of absence). `prepare_release(...)` refuses on a red verdict — a true no-op, the repo left byte-for-byte untouched — else cuts the CHANGELOG (`[Unreleased]` → `[X.Y.0]`, re-seeding a fresh `[Unreleased]`), bumps `pyproject` (line-anchored regex — no TOML round-trip, no new dependency), commits + annotated-tags **locally**, prepends the vault `release_log.md`, and returns the merge+push handoff. The **"never push" boundary is structural**: the injected `ReleaseGit` seam (real `SubprocessReleaseGit` + recording `FakeReleaseGit`) has no `push`/`merge` method, so prepare *cannot* ship. Wired into `driver.run()` via a new injected `release` seam invoked after `converge()` at plan-complete — a converge halt returns before it, a refused release halts the run, a prepared release completes it. The shared `all_findings_clean` predicate moved to `findings.py` (used by both converge and release); `__main__._make_release` is the composition root that gathers the facts for the pure verify then prepares (dogfood-validated, like `_make_converge`).
- Converge loop (`orchestrator/converge.py`) — drives open **blocking** review findings to clean by looping *fix → gate → scoped re-verify*, or halts. Pure deterministic control flow, **no LLM in the loop**: it re-reads the three findings files from disk each round and gates convergence on `verdict == "clean"` for all three (the verifier-owned, un-gameable signal), discarding the fixer's return entirely. Terminates by construction — halts at `rounds ≥ max_rounds` (round cap) or a red gate after a fix. Built on injected seams (`read_states`, `run_verify`) so the whole state machine is unit-tested behind `FakeProvider` + `FakeGate`: the full matrix — already-clean (zero rounds), fix→verified (one round), reopen, round-cap halt, red-gate-after-fix — is green with no real roles. Wired into `driver.run()` via a `converge` seam invoked after `fanout()` at plan-complete (they communicate through the findings files on disk, not return values); a converge `HALTED` propagates to a run halt.
- End-of-plan fan-out (`orchestrator/fanout.py`) — `run_fanout(...)` runs the three read-only roles (review ‖ security ‖ simplify) over the frozen `base..HEAD` diff, composing P1–P3: for each role it builds `read_only_profile` (P2), injects the diff as a file via `run_role_with_diff` (P2), emits `role-spawn`/`role-returned` status events (P1), and collects the verdict via `read_findings_state` (P3). Sequential (a plain loop — parallel is a noted-not-built optimization) and data-driven (one loop over a `RoleSpec` table, not three near-identical functions). Wired into `driver.run()` via a new injected `fanout` seam invoked once at plan-complete (a halted build never fans out; a build-only run defaults to a no-op). Fully unit-tested behind a recording `FakeProvider` (three read-only spawns over the frozen diff, per-role events, verdicts collected); the first live run — including `simplify.md`'s first-ever execution — is the P4 dogfood (pending). `__main__` wires the real fan-out: a closure that computes the frozen diff at invoke-time (not bind-time, since the final `HEAD` doesn't exist until the build finishes), plus a `--base` arg, the three role prompts, and plan-version resolution.

### Added

- Role summaries surfaced on the status stream — `RoleReturned` now carries the role's final message (`summary`, filled from the parsed `RoleResult.result`), and `render` shows a trimmed gist under the returned line (`↳ …`; full text in `events.jsonl`). So when a role **halts intentionally** — a coder stop-condition such as *the plan contradicts reality* — you see **why** inline instead of a bare "phase did not advance". Surfaced by the first dogfood: the coder correctly halted on a real scheduling infeasibility (a weekly-rest constraint that made the example roster impossible) and asked for a decision, but the reason was being discarded.
- Graceful provider-error handling — `ClaudeCodeProvider.run_role` now raises a typed `ProviderError` on a non-zero `claude -p` exit (an API error or subscription usage limit) instead of letting `CalledProcessError` crash the run with a raw traceback. `driver.run()` catches it around the coder spawn and turns it into a clean, observable **halt** (emits a `halt` event + `run-summary`, returns `HALTED`), so the run stops **resumably** — re-running picks up from the last committed phase via disk state — and `__main__` backstops the same error in the fan-out/converge/release stages with a readable message + a distinct exit code. Documented behaviour surfaced by the first live dogfood, where a subscription usage limit crashed the run mid-phase.
- `--model` and `--effort` flags on `python -m orchestrator run` — pin every role's `claude -p` invocation to a specific model (e.g. `claude-opus-4-8`) and reasoning effort (`low|medium|high|xhigh|max`), threaded via `ClaudeCodeProvider(model=…, effort=…)` → `build_command`'s optional `model`/`effort` params (append `--model` / `--effort`). `--model` defaults to the `claude` CLI's own default; `--effort` defaults to **`medium`** (a well-specified plan needs solid execution, not maximal deliberation, and higher tiers drain reasoning tokens fast; `high`/`xhigh`/`max` stay available via `--effort` for harder work). So a run is reproducible on an explicit model + effort instead of an implicit machine default.

### Changed

- Reverted the coder to the **per-phase** model (the warm whole-plan coder was a wrong turn the first dogfood exposed): `coder.md` now builds **exactly one phase per spawn** then STOPs, and the driver's existing per-phase loop gates + detects advance + re-spawns per phase. This restores per-phase un-gameable gating, **per-phase CLI/log visibility** (each phase emits `phase-start` → `gate ✓` → `advanced`), and **crash resilience** (a failure loses only the current phase; committed phases are safe) — the three gaps that appeared when a subscription limit crashed a warm 6-phase session mid-P3. `coder.md` also gains **resume-mid-phase detection**: on a `git status` showing uncommitted work it recognises an interrupted phase, continues it (rather than restarting), and logs that it resumed.
- Cleaner status rendering (`status.py`): `render` trims the verbose `current_phase` to a short one-line CLI label (was printing the whole multi-line phase prose), names each role (`review`/`security`/`simplify`/`coder`) instead of hardcoding "coder", and marks a phase advance as `✅ phase done → advanced to …` and a halt as `⛔ halted: …`.
- Prompt refactor for the deterministic loop (`prompts/`) — slimmed the three read-only role prompts (`reviewer.md`, `security.md`, `simplify.md`) to what the orchestrator *can't* supply: the review/audit/simplify **rubric** + the **findings-file contract** + **verify mode**, dropping the now-dead orchestration (the `bash` parameter-resolution + `git diff` + gate-running that the read-only profile denies anyway). The orchestrator now **prepends an Inputs block** (mode · diff path · findings path · head SHA · plan/context) to each read-only role at spawn (`run_fanout`), since the role has no shell to resolve paths itself. Switched the coder to the **warm whole-plan** model: `coder.md` builds every remaining phase in one session (committing per phase), and `coder-per-phase.md` is **removed** (per-phase gating was a v0.1 scaffold) — the orchestrator now runs its un-gameable gate once at plan-end plus the fan-out. Extracted the converge fixer into a standalone `fixer.md` (was `coder.md` Mode B) and **rewired `_make_converge` to use it** — a real fix, since `__main__` had been handing the *build* prompt to the converge loop as its fixer. **Reconciled the findings-file path:** `run_fanout` writes/reads `implementation_plans/${version}_{role}.md` (was the vault root), the single location the prompts + `_make_converge`'s reader already used — previously fan-out wrote where converge wasn't looking, so the loop could never have seen the findings.
- Gate config relocated to `.minions/minions.toml` (`gate.py` `read_gate_commands`, was `repo/minions.toml`) — consolidating the committed gate config with the generated `.minions/` run artifacts (one framework dir per target, behind a selective ignore `.minions/*` + `!.minions/minions.toml` in the target). A missing config now raises a clear `FileNotFoundError` ("the target must ship .minions/minions.toml") instead of a bare traceback deep in a run. `tests/test_gate.py`, `README.md`, and `docs/modules/gate.md` updated to match.
- Unified the coder-specific `CoderSpawn`/`CoderResult` status events into generic `RoleSpawn`/`RoleReturned` (carrying a `role: Role` — `Literal["coder","review","security","simplify"]`, one alias reused by `fanout.RoleSpec.name`), so the fan-out roles reuse the same spawn/returned events instead of a parallel pair. The coder is now `role="coder"`. (The result event is named `RoleReturned` to avoid clashing with `provider.RoleResult`.) `is_in_progress` and the renderer follow through one `RoleSpawn` case. `_no_emit` moved from `driver.py` to `status.py` so `driver` and `fanout` share it without an import cycle.

 — `read_findings_state(path) -> FindingsState | None` reads a role's findings file into a typed, validated convergence verdict (`verdict` / `open_blocking` / `round` / `head`), reusing `state.py`'s `parse_frontmatter` (no new parser). `FindingsState` is a frozen Pydantic model (a trust-boundary read *with structure worth validating* — ints to coerce, a closed `Literal["clean","changes-requested"]` verdict that rejects a typo at read time), so `model_validate` coerces the ints and ignores the extra frontmatter keys in one line. A missing file returns `None` (a not-yet-run role, not a crash), keeping `verdict` strict and forcing callers to handle "not run". This is the orchestrator's un-gameable convergence signal — owned by the verify pass, read from disk, never trusted from the fixer's word. Unit-tested (parse + coercion, `None` on missing, `ValidationError` on an unknown verdict).
- Diff supply for read-only roles (`orchestrator/diff.py`) — `compute_diff(repo, base, head)` returns the diff for a commit range via list-argv git (`git diff base..head`, no shell) behind an injected runner seam (the real `_run_git` uses `check=True` — a failing diff is an error to surface, unlike the gate's captured red). Two scopes serve two callers: frozen `base..HEAD` (the whole feature) for the fan-out, and `head..HEAD` (just the fix) for scoped re-verify. `run_role_with_diff(...)` writes the diff to a file under the target's `.minions/` and runs the role, so the prompt carries only the path — a large diff never bloats it. The role-agnostic primitive the P4 fan-out will compose per role. Unit-tested behind an injected runner + `FakeProvider`; no real git or `claude`.
- Read-only role permission profile (`read_only_profile(findings_file)` in `orchestrator/provider.py`) — denies `Bash` and `Edit` (bare-tool denies, the sound regime of the v0.1 Q1 finding) and allows `Write` only to the role's single findings file (`Write(<path>)`). A factory over the existing `Profile` (no schema change; `build_command` emits it unchanged), deliberately avoiding a bare-`Write` deny so deny-precedence can't cancel the scoped allow. `Bash` denied is why a read-only role can't `git diff` itself — hence the orchestrator-supplied diff above.
- Status/event stream (`orchestrator/status.py`) — the run is now observable without any LLM in the loop. A typed, timestamped **`Event`** schema (a Pydantic discriminated union on `kind`: `phase-start`, `role-spawn`, `role-returned`, `gate-step`, `advance`, `halt`, `run-summary`; timestamps are `AwareDatetime`, rejecting naive datetimes at the boundary) is written to disk two ways — an **append-only history** (`events.jsonl`, one JSON line per event) and a **current-state snapshot** (`status.json`, the latest event) — via a single `emit` that keeps them in step. A pure, exhaustive `render(event) -> str` (a `match` with no `case _`, so `ty` enforces a line for every variant) projects the stream to stdout, and `is_in_progress` derives "a role is still running" from a dangling `coder-spawn` in the snapshot. Fully unit-tested (round-trip, snapshot, render, in-progress) with no disk-less logic left untested.
- Instrumented the build-spine loop: `driver.run()` gains an injected `emit_event` sink (defaulting to a no-op — observability is a side-channel the driver's logic never depends on) and emits the event sequence around each phase. The coder's returned `RoleResult` is now **captured** to fill the `coder-result` event while `decide` still **discards** it for the advance verdict (surfaced for observation, never trusted); every terminal path — complete, decision-halt, and the runaway guard — ends with a `run-summary`. Instrumentation covered by spy-injected tests (emitted kind-sequence + key fields).
- Live status sink wired in `orchestrator/__main__.py`: `_make_emitter` roots an `events.jsonl` + `status.json` pair under the target's `.minions/` (fresh log per run) and `emit_and_render` writes each event to disk **and** renders it to stdout, so a real run is no longer silent.
- `Makefile` with `make fix` (mutating: `ruff format` + `ruff check --fix`) and `make gate` (verify-only, the definition of done: `ruff format --check` → `ruff check` → `ty check` → `pytest`) — kept strictly separate so the gate can never auto-fix its way to green.
- Restructured `docs/` to the documentation standard: one file per source module under `docs/modules/` (each with light frontmatter, a narrative header for the human, a per-symbol reference with copied signatures and cross-links for the agent, and a single data-flow diagram), a present-tense `architecture.md` (invariants + one dependency graph, no phase/roadmap tables), and a front-door `README.md`. Dropped the build-progress/version tags (`[BUILT Pn]`, `(v0.2 Pn)`, `dogfood pending`) and the inline design-rationale essays (rationale now lives in the vault's `decisions.md`, linked); dissolved `data-flow.md` and the mega-file `modules/orchestrator.md` into the per-module docs.
