# PRD v0.1 — Add & list tasks

**Version:** v0.1 · an example PRD for the planning vault (the shape `mf-order` produces).

## Problem

A person wants a frictionless way to jot tasks from the terminal and see them later, without opening an app.

## Outcome

`tasknip add "<text>"` records a task; `tasknip list` prints all tasks with an index. State persists across runs.

## Requirements

- **R1 — Add a task.** `tasknip add "<text>"` appends a task to the store. Acceptance: WHEN `add "buy milk"` runs
  THEN the store contains a task with text "buy milk" and `list` shows it.
- **R2 — List tasks.** `tasknip list` prints each task with a 1-based index. Acceptance: WHEN two tasks exist THEN
  `list` prints them in insertion order, numbered `1` and `2`.
- **R3 — Persistent store.** Tasks survive between invocations. Acceptance: WHEN a task is added in one process
  THEN a fresh `list` process shows it.
- **R4 — Empty state.** Acceptance: WHEN no tasks exist THEN `list` prints `no tasks` and exits `0`.

## Constraints

- No new runtime dependency (stdlib only — `argparse`, `json`).
- Store at `~/.tasknip/tasks.json`; create the directory if missing.

## Non-goals

- Editing or deleting tasks. Marking done (v0.2). Due dates (v0.3). Sync / multi-device.

## Delivery outline

1. Store module (load/save JSON; create the dir).
2. `add` command + test.
3. `list` command (incl. the empty state) + test.
4. CLI wiring (`argparse`) + a smoke test.

## Decisions settled

- Single JSON file store; `argparse` CLI (see [decisions.md](../decisions.md)). No open questions.
